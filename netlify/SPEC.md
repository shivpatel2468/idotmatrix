# Website and Netlify spec (`site/`, `netlify/`, `netlify.toml`)

Parent: [root SPEC.md](../SPEC.md). How: [docs/WEB_APP.md](../docs/WEB_APP.md) § Build and deploy; the browser app:
[web/webapp/SPEC.md](../web/webapp/SPEC.md).

## Purpose

idotmatrix.com: the product website (static pages in `site/`, generated by `scripts/build_site_media.py` →
`build_site_data.py` → `build_site_pages.py`), the web app under `/app/`, and two Netlify Functions: the CORS proxy
(`/app/proxy`) and WebRTC signalling (`/app/signal`). Netlify runs no build; `site/` is committed fully generated.

**Where the public copy lives.** The website that is deployed is built from the local `website` branch (a separate local
worktree, never merged into `main`), which carries the legal-review copy on top of `main`: DeskDot branding, "unofficial"
wording (not affiliated with the panel's maker), an 18+ gate and "play money" copy for the casino, renamed games,
Privacy / Terms / Download / Licences pages, no rake. Features reach it by cherry-picking from `main`. `main`'s `site/`
is the generator output without those legal edits.

## Requirements

- **R-SITE-1** Generated site data is valid and current; every app has a real preview and a page; every page has the
  standard head and chrome; the sitemap lists every page; there are no broken internal links.
  Tests: `tests/test_site_data.py::test_generator_writes_valid_json_for_every_app`,
  `tests/test_site_data.py::test_committed_site_data_is_current`,
  `tests/test_site_data.py::test_every_app_has_a_real_preview_and_a_page`,
  `tests/test_site_data.py::test_pages_have_standard_head_and_chrome`,
  `tests/test_site_data.py::test_sitemap_lists_every_page`, `tests/test_site_data.py::test_no_broken_internal_links`.
- **R-SITE-2** CSP: the website's pages have a strict policy (one hashed inline script); `/app/*`, `/p/*`, `/tv/*` have
  the web app's own policy (Pyodide CDN, `'wasm-unsafe-eval'`, same-origin worker) and never both; the headers match
  the generated pages. Tests: `tests/test_site_data.py::test_netlify_config_matches_the_site`,
  `tests/test_web_play.py::test_phone_pages_split_for_the_join_page_csp`.
- **R-SITE-3** The site says DeskDot, never the old name. Tests: `tests/test_site_data.py::test_site_says_deskdot_not_dotdeck`.
- **R-SITE-4** The CORS proxy is a GET-only host allowlist (no credentials, no cookies, size cap, redirects stay on the
  allowlist). Tests: `tests/test_web_apps.py::test_the_proxy_is_a_strict_get_only_allowlist`, `tests/js/cors_proxy.test.mjs`.
- **R-SITE-5** Signalling validates input, expires rooms, and hands out relay (TURN) credentials only for a live room.
  Tests: `tests/js/signal_core.test.mjs`, `tests/test_web_play.py::test_join_sources_exist_and_signal_route`.
- **R-SITE-6** Legal copy on the deployed site: "unofficial / not affiliated", casino behind an 18+ gate with
  play-money wording, no trademarked game names, Privacy and Terms pages with a real contact address.
  Tests: none on `main` (gap — lives in the `website` branch).

## Invariants

- **I-SITE-1** Deploy only from the `website` worktree; production deploys only when the user asks (each costs Netlify
  credits) — use free preview deploys otherwise. Never touch other Netlify sites on the account.
- **I-SITE-2** No inline scripts on CSP-protected pages except the one hashed script; a new inline script means a new
  hash in `netlify.toml` (checked by R-SITE-2).
- **I-SITE-3** Security headers on everything: `nosniff`, `DENY` framing, HSTS, a strict referrer policy.
- **I-SITE-4** Private legal notes (`docs/LEGAL_REVIEW*.md`) never go in the public repo.
- **I-SITE-5** `netlify/node_modules` is a real `npm install` before a deploy (the signal function bundles
  `@netlify/blobs`).

## Interfaces

`/app/proxy?url=…` (GET), `/app/signal` (POST/GET, rooms by code), rewrites `/p/*` and `/tv/*` → `/app/join/`;
`site/apps.json` (CORS `*`). Environment: `TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL` (Netlify env, never git).
