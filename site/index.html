Run it with your AI agent

Paste one prompt into Claude Code, Gemini CLI, Codex, Cursor or any coding agent with a terminal. It clones the repo, installs everything with uv, starts the simulator, and waits for you before it touches the real panel. Then it connects itself to the panel through the MCP server.

Copy the prompt

It follows the repo's own rules in CLAUDE.md: only the engine talks Bluetooth, and nothing gets "fixed" by editing source.

2

Pick your agent below for the exact command and where its MCP config lives.

3
Watch the simulator

The studio opens at http://127.0.0.1:8765 with a simulated panel. No hardware needed yet.

setup-prompt.txt 
Set up DotDeck for me: an open-source engine, studio and MCP server for the
iDotMatrix 32×32 LED panel. Repository: https://github.com/shivpatel2468/idotmatrix

Work step by step and tell me what you are doing before each step.

1. Check prerequisites: git, uv (https://docs.astral.sh/uv/, install it if missing;
   it brings its own Python 3.13) and Node.js 20+ (only to build the studio once).
   Tell me whether this machine has Bluetooth LE.
2. Clone the repo into a folder called dotdeck and work inside it:
     git clone https://github.com/shivpatel2468/idotmatrix.git dotdeck
3. Read CLAUDE.md and README.md before doing anything else, and follow their rules.
   Above all: only the DotDeck engine may talk to the panel over Bluetooth. Never
   connect to it with any other tool, and never disconnect it on purpose.
4. Install the Python dependencies:   uv sync --extra mcp
5. Build the studio once (in web/):   npm ci, then npm run build
6. Start the engine with the simulated panel, in the background:
     uv run dotdeck serve --sim
   Wait until http://127.0.0.1:8765 answers, then tell me to open it.
7. STOP and ask me before touching real hardware. When I confirm the panel is on
   and the iDotMatrix phone app is closed:
   - stop the simulator
   - uv run dotdeck scan      (finds the panel, named IDM-xxxxxx)
   - copy dotdeck.example.toml to dotdeck.toml and set address = "<the MAC found>"
   - uv run dotdeck doctor    (draws a test pattern; ask me whether I can see it)
   - uv run dotdeck serve     (the real panel; leave it running)
8. Connect yourself to the panel through DotDeck's MCP server (docs/MCP.md):
   a stdio server started with
     uv run --project <absolute path to dotdeck> dotdeck-mcp
   with env DOTDECK_URL=http://127.0.0.1:8765. Then call panel_snapshot,
   list_apps, and show_app with "clock" to prove it works.
9. Finish with a short summary: what is running, the studio URL, how to stop and
   restart it, and where my dotdeck.toml is.

If something fails, read the error and the docs (docs/DEPLOY.md, docs/MCP.md,
docs/HARDWARE_PROTOCOL.md) and fix the setup. Do not edit DotDeck's source code to
work around a problem; tell me instead.

Step by step

Run it yourself

About ten minutes from nothing to a live panel. Every command here is the one the README uses; each step links to the file that explains it.

  1. Get the prerequisites

    • uv, the Python manager. It installs Python 3.13 for you; your system Python is untouched.
    • Git, and Node.js 20+ to build the studio once (and for studio development).
    • A computer with Bluetooth LE within a few metres of the panel. No panel yet? You can still do everything up to step 5.
    • Close the iDotMatrix phone app. The panel accepts one Bluetooth connection at a time.
    install uv (PowerShell)
    PS> powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
    install uv
    $ curl -LsSf https://astral.sh/uv/install.sh | sh
    uv install docsREADME: Quick StartREADME: Compatibility

  2. Clone the repo

    $ git clone https://github.com/shivpatel2468/idotmatrix.git dotdeck
$ cd dotdeck
    github.com/shivpatel2468/idotmatrixdocs/ARCHITECTURE.md

  3. Install the engine and the MCP server

    One command installs Python 3.13 and every dependency into a local .venv.

    $ uv sync --extra mcp
    pyproject.tomlADR 0002: Python, uv, FastAPI

  4. Build the studio once

    The engine serves the built studio from web/dist. You only need Node again if you work on the studio itself.

    $ cd web
$ npm ci
$ npm run build
$ cd ..

    Hacking on the UI? npm run dev in web/ gives hot reload on :5173, proxied to the engine.

    web/docs/STUDIO_UI.md

  5. Try it on the simulator

    Everything runs against a simulated panel: every app, every game, the studio and the MCP server.

    $ uv run dotdeck serve --sim

    Then open http://127.0.0.1:8765. Pick an app, change a setting, press ▶ Play on a game.

    README: The First Five Minutesdocs/API.md

  6. Find your panel and save its address

    Stop the simulator (Ctrl+C), switch the panel on, then scan. It shows up as IDM-xxxxxx.

    $ uv run dotdeck scan

    Copy dotdeck.example.toml to dotdeck.toml and put the MAC in. The file is git-ignored, so it never leaves your machine. Leave address empty to use the first IDM-* panel found.

    dotdeck.toml
    address = "AA:BB:CC:DD:EE:FF"   # from `dotdeck scan`
device = "ble"                  # "sim" = simulator
lan_studio = false              # true = full studio for other devices on your Wi-Fi
    dotdeck.example.tomldocs/HARDWARE_PROTOCOL.md

  7. Check the link

    Connects and draws a test pattern on the real panel. If you see it, Bluetooth is good.

    $ uv run dotdeck doctor
    src/dotdeck/cli.pyADR 0009: paced writes

  8. Run it for real

    $ uv run dotdeck serve        # → http://127.0.0.1:8765

    Run the colour wizard once (Settings → Display & colour) so photos and album art match your LEDs. Want an app as a PNG without hardware? uv run dotdeck preview clock --out clock.png.

    README: The StudioREADME: Games & Multiplayer

  9. Connect an AI agent (optional)

    With the engine running, register the MCP server and your agent can see the panel, run apps, draw pixel art and notify you.

    $ claude mcp add dotdeck -- uv run --project /path/to/dotdeck dotdeck-mcp

    Other agents: see the agent tabs above.

    docs/MCP.mdsrc/dotdeck/mcp_server.py

  10. Keep it on 24/7 (optional)

    Raspberry Pi

    Zero 2 W / 3 / 4 / 5: built-in BLE, 1–3 W. Build the studio on your computer, copy the folder over, run the installer (uv + a systemd service). Then open http://raspberrypi.local:8765.

    $ scp -r . pi@raspberrypi.local:~/dotdeck
pi$ cd ~/dotdeck && bash scripts/install-pi.sh
    scripts/install-pi.shdocs/DEPLOY.md

    Android phone Beta

    The whole engine runs on a spare Android 8+ (64-bit) phone as a foreground service and restarts after a reboot. It builds and its Bluetooth bridge is unit-tested, but it hasn't been run on a real phone yet.

    android/README.mdADR 0011

    Only one device can hold the panel's link: stop DotDeck on the laptop when the Pi or phone runs it.

Why DotDeck

Everything your panel was missing

One engine owns the panel's Bluetooth link and keeps it smooth. Everything else (the studio, your phone, scripts, AI agents) goes through its HTTP API.

Games & multiplayer

25 games, 21 of them for 2–4 players on your Wi-Fi. The panel shows a QR code and friends' phones become controllers: d-pad, stick, swipe, tap, tilt or a real gamepad. Every game plays itself as a screensaver until you press a key; B opens modes, maps and themes, then a FIFA-style side select.

AI agents via MCP

21 tools let Claude and other agents look at the panel (as an image), run any app, change any setting, draw pixel art, push notifications and drive the playlist.

Smooth on the hardware

Loops are baked once into a GIF the panel plays with its own firmware: perfectly smooth, zero Bluetooth traffic. Only live data streams.

Live, location-aware data

Weather, flights overhead, quakes, launches, tides, markets, scores and air quality from 45+ free sources. Almost none need a key.

Private by design

No account, no cloud, nothing sent to the panel's manufacturer. It runs on your machine; keys and your panel's address stay in a git-ignored file.

Always on: Pi or Android

Run it 24/7 on a Raspberry Pi with one installer, or on a spare Android phone (beta). When your computer sleeps the panel hands off to its own clock or a baked loop.

A studio for every screen

Library, playlists, presets and live settings, with an LED-accurate preview. Every form is generated from the app's schema, on desktop and phone.

One file per app

A pydantic settings model and a pure render(). Drop a file in plugins/ and it appears in the studio with a form. App SDK.

New · Fly Brain

Questions

FAQ

Is this the official iDotMatrix app?

No. DotDeck is an independent, community-built project. It is not affiliated with, endorsed by or supported by the makers of iDotMatrix; the name is only used to say which panels it works with. It talks to your own panel over Bluetooth and sends nothing to the manufacturer.

Which panels does it work with?

The iDotMatrix 32×32 RGB panel (it advertises as IDM-xxxxxx) is verified on hardware. Other sizes share the protocol but are untested, and every app is designed for 32×32.

Do I need the iDotMatrix phone app?

No, and you should close it while DotDeck runs: the panel accepts one Bluetooth connection at a time.

Does it cost anything or need an account?

No. It's MIT-licensed, runs locally and has no account. Almost every live data source is free and key-less; a few optional ones (GitHub token, Home Assistant, your own services) use your own credentials. See API keys & costs.

Can I try it without a panel?

Yes: uv run dotdeck serve --sim runs the engine, studio and MCP server against a simulated panel that looks like the real LEDs.

Why are some animations perfectly smooth and others not?

Bluetooth carries about 5–9 live frames a second. So deterministic loops are baked once into a GIF that the panel plays with its own firmware, perfectly smooth. Only things that change with live data are streamed. The Apps explorer marks each app as a baked loop, live stream or firmware feature.

What is MCP, and which agents work?

The Model Context Protocol lets AI agents call tools. DotDeck's MCP server (dotdeck-mcp) is a thin client over the engine's HTTP API, so any MCP client works: Claude Code and Claude Desktop are documented in docs/MCP.md, and Gemini CLI, Codex and Cursor use the same stdio command.

Can I write my own app?

Yes. An app is one Python file: a pydantic settings model and a pure render() that draws with clipped primitives and bitmap fonts. Drop it in plugins/ and the studio builds its form. Start with docs/APP_SDK.md and docs/DISPLAY_DESIGN.md.

Does the Android app work?

It's in beta: it builds and its Bluetooth bridge is unit-tested, but it hasn't been run on a real phone yet. Build steps are in android/README.md.

Something's wrong. Where do I report it?

Open an issue on GitHub. Security issues: see SECURITY.md. Contributions: CONTRIBUTING.md.
